# /magento:init

Work from the project root (the directory containing `bin/magento`). Do the steps in order; never write anything before step 5.

## 1. Detect

Run: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/detect-project.sh" .`

- Exit code 2 → print its stderr line (`not a Magento root: …`) and stop. Nothing is written.
- Any other non-zero exit → show stderr and stop.
- Exit 0 → the stdout JSON is FACTS. Keys: `magento.edition`, `magento.version`, `php`, `modules[]{name,path}`, `themes[]{area,name,path,parent}`, `hyva`, `env`, `tooling{phpcs,phpstan,phpunit}`, `mode`.

## 2. Plugin version

Read `version` from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`. Call it VERSION.

## 3. Derive

- FRONTEND = `Hyvä` if FACTS.hyva is true or any theme parent is `Hyva/default`; otherwise `Luma`.
- LUMA = `true` if FACTS.hyva is false, or any frontend theme's parent is not `Hyva/default`, or there are no themes; else `false`.
- HYVA = FACTS.hyva as `true`/`false`.
- PREFIX by FACTS.env: `warden` → `warden env exec php-fpm`; `ddev` → `ddev exec`; `docker` → `docker compose exec <php-service>` (append the sentence "— replace `<php-service>` with the PHP service name from your compose file"); `native` → no prefix: the Environment line reads ``run CLI as `bin/magento …` `` with nothing before `bin/magento`.
- EDITION = `Magento Open Source` for `open-source`, `Adobe Commerce` for `commerce`, `Magento (edition unknown)` otherwise.

## 4. Render the CLAUDE.md block

Write this to a temp file (use the session scratchpad directory if one is listed in your system prompt, else `mktemp`), substituting values. Keep the markers as the first and last lines. Where a value is `null`, write `unknown`.

```
<!-- magento:begin -->
## Magento project (generated by the magento plugin vVERSION — rerun /magento:init to refresh)

- **Edition:** EDITION FACTS.magento.version · PHP FACTS.php · mode: FACTS.mode
- **Frontend:** FRONTEND — themes: <name → parent, comma-separated | none in app/design>
- **Custom modules:** <name (path), comma-separated | none in app/code>
- **Environment:** <Warden | DDEV | Docker Compose | native> — run CLI as `PREFIX bin/magento …` (native: PREFIX is empty — write `bin/magento …`, with the backtick immediately followed by `bin/magento`, no leading space)
- **Tooling:** phpcs <✓|✗> · phpstan <✓|✗> · phpunit <✓|✗>

### Working here
- Use the CLI prefix above for every `bin/magento` and `composer` command.
- After schema changes: `setup:db-declaration:generate-whitelist --module-name=<Module>`, then `setup:upgrade`, then `cache:clean`. After other module/config changes: `setup:upgrade` (new modules) or `cache:clean config compiled_config` (plugin lists live in `compiled_config`).
- Conventions Claude follows in this repo: `.claude/rules/magento.md`. Deeper guidance lives in the `magento:*` skills (module, data, api, frontend-luma, frontend-hyva, ops, quality).
- Before finishing PHP changes: `vendor/bin/phpcs --standard=Magento2 <changed paths>`.
<!-- magento:end -->
```

## 5. Render the rules file and apply

```
bash "${CLAUDE_PLUGIN_ROOT}/scripts/render-rules.sh" --version VERSION --hyva HYVA --luma LUMA > <rules temp file>
bash "${CLAUDE_PLUGIN_ROOT}/scripts/apply-init.sh" --block <block temp file> --rules <rules temp file> --root .
```

## 6. Report

Print the two summary lines from `apply-init.sh` verbatim, then:
- if the rules file was "left alone (owned by you)": one sentence saying the header line was removed so it is now user-owned, and how to regenerate (delete the file and rerun).
- one line: "Review `CLAUDE.md` and commit both files."
