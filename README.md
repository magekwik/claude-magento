# claude-magento

Claude Code plugins for Magento, by [Magekwik](https://magekwik.com).

This repository is a Claude Code **plugin marketplace** (`magekwik`) containing one plugin today:

| Plugin | What it does |
|---|---|
| [`magekwik-magento`](plugins/magento/) | Makes Claude Code a competent Magento Open Source 2.4 developer: eight knowledge skills, `/magekwik-magento:init` to set a project up, `/magekwik-magento:review` for Magento-aware code review. |

**Supports:** Magento Open Source 2.4.4 – 2.4.9 · PHP 8.1 – 8.5 · Luma and Hyvä frontends. Adobe Commerce-only features are referenced, not covered in depth.

---

## Install

```
/plugin marketplace add magekwik/claude-magento
/plugin install magekwik-magento@magekwik
```

Try it without installing (one session, loaded in place):

```
claude --plugin-dir ./plugins/magento
```

Update later with `/plugin marketplace update magekwik`.

**Requirements:** Claude Code 2.1+, `git`, `bash`. Optional: `gh` (PR review), `vendor/bin/phpcs` with `magento/magento-coding-standard` (PHPCS findings inside reviews).

## What you get

### Skills — loaded automatically when a task touches the area

| Skill | Covers | Try asking |
|---|---|---|
| `magekwik-magento:conventions` | The rulebook: 39 architecture, security, performance, Luma, Hyvä and quality rules, each with the *why* and the PHPCS sniff that enforces it | "Which rule says I can't add a column to `catalog_product_entity`?" |
| `magekwik-magento:module` | Modules, `di.xml` plugins/preferences/virtual types, events and observers, ViewModels, cron, console commands, admin controllers with ACL | "Add a before plugin that rejects cart quantities over 10" |
| `magekwik-magento:data` | `db_schema.xml` and the whitelist, data/schema patches, models and repositories, service contracts, EAV and extension attributes | "Store a brand on every product" |
| `magekwik-magento:api` | `webapi.xml` REST, GraphQL schema and resolvers, ACL, tokens, CSRF | "Expose GET /V1/acme/brands to store managers only" |
| `magekwik-magento:frontend-luma` | Layout XML, `.phtml` templates and escaping, ViewModels, RequireJS/Knockout, LESS, static deploy | "Add a free-shipping notice to the top of every page" |
| `magekwik-magento:frontend-hyva` | Tailwind, Alpine.js, ViewModels, private content, compatibility modules | "Make that banner dismissible on our Hyvä theme" |
| `magekwik-magento:ops` | `bin/magento` workflows, cache types, indexers, modes, logs, Xdebug, Varnish/LiteMage/Redis, upgrades and patches, Warden/DDEV/Docker | "What do I run after changing `db_schema.xml` in developer mode?" |
| `magekwik-magento:quality` | PHPCS with the Magento2 standard, PHPStan, PHPMD, unit and integration tests | "Set up PHPCS for `app/code/Acme` and give me a unit test skeleton" |

Every skill is a short hub (≤ 250 lines) plus reference files read only when needed. Version-dependent behaviour names the version; every reference ends with the documentation pages it was checked against.

### `/magekwik-magento:init` — make a project AI-friendly

Detects edition and version, custom modules, themes (Luma or Hyvä), the dev environment (Warden, DDEV, docker-magento, Docker Compose or native) and tooling, then writes:

- a marked block in `CLAUDE.md` with the facts and the exact CLI prefix for that environment (e.g. `warden env exec php-fpm bin/magento …`);
- `.claude/rules/magento.md` — the rulebook, trimmed to what applies.

Re-running only touches its own block. Delete the rules file's first line to take ownership of it.

```
<!-- magento:begin -->
## Magento project (generated by the magento plugin v1.0.0 — rerun /magekwik-magento:init to refresh)

- **Edition:** Magento Open Source 2.4.9 · host PHP 8.4.10 · mode: production
- **Frontend:** Luma — themes: Acme/default → Magento/luma
- **Custom modules:** Acme_Catalog (app/code/Acme/Catalog)
- **Environment:** Warden — run CLI as `warden env exec php-fpm bin/magento …`
- **Tooling:** phpcs ✓ · phpstan ✗ · phpunit ✓
…
<!-- magento:end -->
```

### `/magekwik-magento:review [branch|PR] [--comment]` — a Magento-aware second reviewer

A read-only subagent reads the rulebook, then the skills relevant to the touched files, then the diff. It runs PHPCS when available and reports in a fixed format you can post straight to a PR:

```
[blocker] app/code/Acme/Catalog/Controller/Index/Save.php:14 — A5
Why: `$name` is concatenated into the INSERT, so any request can inject SQL.
Fix: Drop the raw query; save through a repository, or at minimum use bound parameters.

Verdict: 1 blocker(s), 0 major, 0 minor, 0 nit — not mergeable as is
```

| You type | It reviews |
|---|---|
| `/magekwik-magento:review` | Everything since the default branch, plus staged, unstaged and new code files |
| `/magekwik-magento:review develop` | The same, measured from the merge-base with `develop` |
| `/magekwik-magento:review 42` | GitHub PR #42 |
| `/magekwik-magento:review 42 --comment` | …and posts each finding as an inline PR comment |

## What it looks for

Beyond PHPCS: `ObjectManager` use; plugins on `final`/`private`/`static` methods; raw SQL; legacy install scripts; edits under `vendor/`; core-table schema changes; missing `ADMIN_RESOURCE` or `webapi.xml` resources; mutating GET actions; unescaped output; loads inside loops; `cacheable="false"`; `$this` in templates; Luma JS on a Hyvä theme; missing `strict_types`; `db_schema.xml` changed without the whitelist; patches without dependencies.

---

## Tested against real stores

Before each release the plugin is run against a production-shaped Warden store and a fresh `composer create-project` 2.4.9 install (see `docs/release-checklist.md`). In the 1.0.0 run, Claude scaffolded a module that served its page with HTTP 200 after `setup:upgrade`, exposed it over GraphQL behind a service contract, passed PHPCS on both, and the reviewer's findings on the result were all legitimate.

Eleven eval scenarios (`evals/`) run against fixture projects; five of them fail without the plugin and pass with it — adding a column to a core table, the after-`db_schema.xml` command sequence, the reviewer on a planted bad controller, and both `init` runs.

---

## What it touches, and what it doesn't

- `/magekwik-magento:init` writes `CLAUDE.md` (one marked block) and `.claude/rules/magento.md`. Nothing else.
- `/magekwik-magento:review` writes nothing; it runs `git` and `vendor/bin/phpcs`, `gh` only with a PR number, and posts comments only with `--comment`.
- No hooks, no MCP servers, no network calls of its own, no credentials.

## Development

```
claude --plugin-dir ./plugins/magento                                   # try in place
claude plugin validate ./plugins/magento --strict && claude plugin validate .
bash tests/run.sh                                                       # script unit tests
bash evals/run.sh                                                       # eval scenarios (needs a logged-in claude)
```

CI runs manifest validation, shellcheck, the unit tests, size limits and a content check on every push; evals run on manual dispatch.
